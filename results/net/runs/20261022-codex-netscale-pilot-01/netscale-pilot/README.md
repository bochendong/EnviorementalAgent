# Codex netscale pilot results

2026年10月22日。模型 `gpt-6.1-sol`，思考档位 `high`。

沿用原 `netscale-pilot` 的 Peers、Lockstep、16×4 DAG 和团队工具预算915次，种子为100、101、102。环境在本地运行，模型通过 Codex CLI 服务推理。12组均通过数学验证器验收，每组正确完成65/65个任务。

| 人数 | 平均同步轮数 | 相对单人加速 | 平均工具调用 | 单次团队平均用量 万 tokens | 协调效率 η |
|---|---:|---:|---:|---:|---:|
| 1 | 81.7 | 1.00× | 81.7 | 207.10 | 1.00 |
| 2 | 76.3 | 1.07× | 152.7 | 385.45 | 1.33 |
| 4 | 51.0 | 1.60× | 204.0 | 480.80 | 1.09 |
| 8 | 38.0 | 2.15× | 304.0 | 744.45 | 0.87 |

每行是3个种子的均值。每个同步轮次中，每个活跃成员各执行一步；模拟轮数与服务排队及实际耗时分别计量。

协调效率按先平均轮数、再取比值计算：

$$\eta_N = \frac{T_{\mathrm{ref},N}/T_N}{T_{\mathrm{ref},1}/T_1}.$$

`T_N` 为N人 Codex 团队的平均轮数，`T_ref,N` 为同题同人数脚本参考团队的平均轮数。η衡量相对脚本参考的效率较单人如何变化。8人示例为 `(52/38)/(129/(245/3)) ≈ 0.87`。

正式实验已记录总用量为 **54,534,195 tokens**：输入54,249,651（其中缓存输入17,888,384），输出284,544（其中思考输出157,238）。缓存与思考是子项，不重复相加。统计覆盖2227次成功返回用量的请求；7次服务满载均重试恢复，失败请求无用量回执。开发试跑与外层编码、报告和聊天用量不在统计内。

最终完成率为100%，不代表每次提交都通过。819次提交中780次被接受、39次被拒绝；拒绝原因包括解析32次、表达式过长1次、依赖未就绪5次和重复提交1次。原汇总的 `wrong_submissions` 计入全部被拒绝提交，不能都解释为数学答案错误。验证器检查最终答案或表达式等价性，不检查完整推导过程。

8人相对单人获得2.15倍轮次加速，同时平均工具调用增至3.72倍、协调操作从5次增至约155次。每种人数只有3次运行，适合判断初步趋势。验证器接受合法符号表达式，Codex可省去部分显式计算，脚本参考轮数不是严格最优下界。共享与私有笔记的配对对照尚未开展。
