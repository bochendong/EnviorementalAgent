## Findings

8人获得约4.01倍轮次加速，平均工具调用为单人的约2.00倍，平均token为约1.67倍。η在2人最高，4人与8人低于单人基准；四人组波动较大。按原汇总拟合的USL为σ=0.170、κ=0、RMSE约0.41，本次未观察到随人数增加而变慢的峰值。每种规模仅3次运行，不能据此断言κ恒为0或推断更大规模的曲线。

总计2563次工具调用，包含797次 `apply` 和788次提交。780次提交正确验收，另外8次因重复提交被拒绝，未发现整数答案错误。成功 `apply` 中有17次重复查询；这与原汇总按不同智能体计算的 `duplicate_work` 口径不同。780次正确验收均标记为来自提交者自己的工具结果。

## Token usage

缓存输入与思考输出是子项，不重复相加。用量来自2563次成功请求的CLI回执，与逐组结果逐项一致；本轮没有失败重试，也没有模型接口错误。开发试跑、下界反例的离线计算、外层编码与聊天用量均排除。

## Interpretation limits

新DAG环境避免了旧递推题通过闭式表达式省略计算的问题；本轮按实际轨迹确认了全部节点的计算来源。但验证器本身只验整数答案，未强制执行grain次查询，不能把所列下界当作所有合法策略、所有grain上的严格保证。

独立的[开发反例](../development-bound-audit.json)使用开发种子1、grain 4，复用一次已经通过 `apply` 观察到的函数循环结果，用324步正确完成65个任务，而工作模型给出325步。该反例及[复现脚本](../audit_bound_example.py)不属于本轮grain 1的正式统计，也没有使用真实模型。grain 4的真实模型实验尚未运行。旧递推试跑的T_ref和η不作为扩展性结论。
