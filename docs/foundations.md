# 基础能力对照：先分开流程与算术

阶梯 23670383 的三个第一级案例均卡在规则推断，未进入链选择或协作；但它与旧入门试点同时改变了世界系数、提示、笔记容量和提交门槛。这里单独运行五组配对条件，不改旧记录或旧阶梯的默认设置。

| 条件 | 世界 | 强制步骤 | 计算器 |
| --- | --- | --- | --- |
| small_gated | 旧入门的相同小系数世界 | 有 | 无 |
| small_open | 同上 | 无 | 无 |
| small_open_calculator | 同上 | 无 | 有 |
| wrapped_open | 原阶梯第一级的一般系数世界 | 无 | 无 |
| wrapped_open_calculator | 同上 | 无 | 有 |

全部采用同一份提示、订单输入 2 和 7、32 行动点、40 次模型调用、容量为 2 的空笔记；不走路、不设钱或目标。每组同样运行种子 11、22、33，每个案例独立重建模型上下文和世界。小世界与大系数世界的目标输出自然不同。计算器组的工具集合多出 `calculate`；所有组的提示都说明如果存在计算器就用于算术。

`calculate` 只计算 agent 自己给出的整数表达式，支持加减乘、整除、余数、括号和模逆元。它不访问机器规律、订单答案或候选链，也不拟合公式。agent 仍要决定采样什么、如何推断、怎样验证、何时交付。计算器免费，但每次使用占一次模型调用，记录完整输入与反馈。

两种指标分开报告：

- `order_passed`：实际交付成功。
- `learning_passed`：在交付成功之外，每台机器至少有三个实际采样输入，两条笔记规则均正确，而且两个公开样例都曾得到正确的笔记预测。这个指标在结束后由评估器计算；不对无门槛组强制步骤，不把隐藏答案告诉 agent。

由于只有一条类型正确的链，无门槛组可能不学习就直接交付。不能把这种订单成功当作已经学会推断；也不能把合法捷径称作无效行动。

输出沿用完整请求/响应、工具、环境、回放和源码快照，并逐案例更新 `summary.json`。本次仍关闭 Qwen thinking，输出上限 1024 tokens。三种子只是初步诊断，不是一般能力结论。

```bash
python scripts/run_foundations.py --out results/foundations/local
sbatch slurm/town_foundations.sh
```

先看 small_gated 与 small_open 的差别，再看 wrapped_open 与 wrapped_open_calculator 的差别。基础推断可复现后，再测试多条链、边界规律和互相提问。每项支持都必须写进实验条件，并在后续团队/单人比较中保持一致。

阶梯也提供可选 `--calculator`，默认关闭，旧实验行为保持原样。基础诊断通过后可使用 `LADDER_ARGS="--calculator" sbatch slurm/town_ladder.sh`，记录中会标注此支持；它不自动替 agent 学习任何规则。
